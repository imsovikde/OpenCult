# OpenCult System and UI Invariants (`INVARIANTS.md`)

Every rule below is binary and testable. No pull request or vertical slice may violate any invariant.

| ID | Name | Invariant Statement | Verification Method |
|---|---|---|---|
| `INV-01` | Raw BLE Frame Immutability | Every raw notification frame (`0xCF`, `0xBE`, `0xDF`) from a completed weigh-in is persisted verbatim with hex payload, packet index, characteristic UUID, timestamp, and XOR checksum flag in Room `raw_ble_packets` and Supabase `public.raw_ble_packets` (no `UPDATE` policy on `raw_ble_packets`). | Room + Postgres RLS policy test confirming raw bytes are saved and updates are rejected. |
| `INV-02` | Honest Provenance Labeling | Every displayed metric carries an explicit `MetricProvenance` (`DIRECT_SENSOR`, `BIA_DUAL_FREQ_8E`, `BIA_SINGLE_FREQ`, `ANTHROPOMETRIC_ESTIMATE`). Anthropometric estimates on the 4-electrode `CS-BF01` scale are never labeled as direct 8-electrode measurements. | Unit test on `BodyMetricsEngine` + UI semantics test on provenance badge text. |
| `INV-03` | Physiological Plausibility Gate | When whole-body 50 kHz impedance is absent, non-positive, or outside `150..1200 ohm`, or when segmental `0xBE` limb channels fail validity gates (e.g. socks/dry feet/no handle contact), BIA compartments are suppressed and verified `weight_kg` is saved alone. | Parameterized unit tests for open-circuit, short-circuit, and feet-only Pro sessions. |
| `INV-04` | Health Connect Idempotency | Every Health Connect write assigns deterministic `Metadata.clientRecordId = "opencult:<measurement_uuid>:<record_type>"` and incrementing `clientRecordVersion`, preventing duplicate records across retries, edits, and historical backfills. | JVM unit test verifying deterministic IDs and update version increments. |
| `INV-05` | Instant Zero-Tap Health Connect Sync | With Health Connect permissions granted, locking a weigh-in triggers background `insertRecords` immediately without manual user export; soft-deleting a measurement triggers `deleteRecords` for its deterministic client IDs. | Integration test against fake/mock `HealthConnectClient`. |
| `INV-06` | Offline-First Local Durability | Room SQLite commits every weigh-in and queues a `sync_outbox` row locally in `< 50 ms` before any network or Health Connect call. Offline mode never drops or blocks a weigh-in. | Instrumented/Robolectric database test with network disabled. |
| `INV-07` | Zero-Refresh Realtime Convergence | While signed in and online, Supabase Realtime Postgres Changes (`measurements`, `household_profiles`, `scale_devices`, `health_connect_sync_ledger`) merge into Room and emit onto Kotlin `StateFlow` within `2 s` without manual refresh, ignoring self-echoes via `mutation_id`. | Sync engine unit test with simulated Realtime event + `mutation_id` dedup. |
| `INV-08` | Row-Level Security Enforcement | Every `public` table in Supabase Postgres has both `ENABLE ROW LEVEL SECURITY` and `FORCE ROW LEVEL SECURITY` scoped to `(SELECT auth.uid()) = account_id`. The Android client never holds `service_role`. | SQL migration inspection + cross-user isolation verification query. |
| `INV-09` | Household Ambiguity Safety | Up to 10 active household profiles are supported. Auto-recognition assigns a weigh-in automatically only when exactly one profile's recent rolling weight matches within its configured `auto_match_window_kg` (default `2.5 kg`). Zero or 2+ matches mark `assignment_state = 'pending_review'` for explicit user selection. | Unit tests for 0-match, 1-match, and 2-match household scenarios. |
| `INV-10` | Design Token Exclusivity | Screen composables never hardcode `Color(0x...)`, font sizes, or corner radii; all visual properties resolve through `OpenCultTheme` tokens (`DRD:T-*`). | Lint/grep check across `feature/` modules for raw color or sp/dp literals outside `designsystem`. |
| `INV-11` | Custom Canvas Chart Fidelity | `DRD:C-01` capsule spark-bars, `DRD:C-02` bezier waves, `DRD:C-03` 3-zone segmented arc gauge, `DRD:C-04` stippled dot-matrix bar chart, and `DRD:C-06` 5-segment anatomical body map are drawn via Compose `Canvas` / `DrawScope`, never substituted with stock generic charts. | Code inspection + Compose screenshot verification against `DRD.md`. |
| `INV-12` | Tabular Numerals on Telemetry | Every live weight, heart-rate, impedance, and metric readout uses `fontFeatureSettings = "tnum"` so streaming updates never jitter horizontally. | Typography token check + Compose semantics test. |
| `INV-13` | Floating Dock Inset Clearance | Every scrollable screen adds `dockHeight + navigationBarsPadding + 24.dp` bottom content padding so the detached `#0F1115` dock and `#2185F7` Measure FAB never clip content. | Compose layout bounds test on compact (`360dp` width) viewport. |
| `INV-14` | Dual-Scale Coexistence | Both Cult Smart Scale Pro (8-electrode `CULT*`) and Cult Smart Body Fat Scale (4-electrode `CS-BF01`) pair and log to the same household account without re-onboarding or schema changes. | `ScaleProtocolRouter` unit test switching between `0xCF` weight-only and `0xCF + 0xBE + 0xDF` streams. |
| `INV-15` | Secret and Reference Exclusion | `Both/`, `.env` / `.env.*` (except `.env.example`), keystores, and credentials remain ignored by `.gitignore` and never enter git commits. | `git check-ignore` + secret regex gate prior to every commit. |
| `INV-16` | Tombstone Soft Delete | Deleting a measurement sets `deleted_at` rather than hard-deleting locally first, so soft deletes propagate across Supabase Realtime and Health Connect before optional compaction. | Sync + Health Connect deletion propagation test. |
