# OpenCult System, UI, and Motion Invariants (`INVARIANTS.md`)

> **Precedence:** `AGENTS.md` > `TRD.md` > `PRD.md` > `INVARIANTS.md` > `HALL_OF_SHAME.md` > `MICROENGINEERING.md` > `MOTIONENGINEERING.md` > `DRD.md` > approved Open Design prototype.
> Every rule below is binary and testable. No pull request or vertical slice may violate any invariant.
> **Living Update Rule (`INV-23`):** Whenever a bug or regression is fixed, update `HALL_OF_SHAME.md` AND add or tighten an invariant below (plus `MICROENGINEERING.md` / `MOTIONENGINEERING.md` for UI/motion issues) in the same commit.

| ID | Name | Invariant Statement | Verification Method |
|---|---|---|---|
| `INV-01` | Raw BLE Frame Immutability | Every raw notification frame (`0xCF`, `0xBE`, `0xDF`) from a completed weigh-in is persisted verbatim with hex payload, packet index, characteristic UUID, timestamp, and XOR checksum flag in Room `raw_ble_packets` and Supabase `public.raw_ble_packets` (no `UPDATE` policy on `raw_ble_packets`). | Room + Postgres RLS policy test confirming raw bytes are saved and updates are rejected. |
| `INV-02` | Honest Provenance Labeling | Every displayed metric carries an explicit `MetricProvenance` (`DIRECT_SENSOR`, `BIA_DUAL_FREQ_8E`, `BIA_SINGLE_FREQ`, `ANTHROPOMETRIC_ESTIMATE`). Anthropometric estimates on the 4-electrode `CS-BF01` scale are never labeled as direct 8-electrode measurements. | Unit test on `BodyMetricsEngine` + UI semantics test on provenance badge text. |
| `INV-03` | Physiological Plausibility Gate | When whole-body 50 kHz impedance is absent, non-positive, or outside `150..1200 ohm`, or when segmental `0xBE` limb channels fail validity gates (e.g. socks/dry feet/no handle contact), BIA compartments are suppressed and verified `weight_kg` is saved alone. | Parameterized unit tests for open-circuit, short-circuit, and feet-only Pro sessions. |
| `INV-04` | Health Connect Idempotency | Every Health Connect write assigns deterministic `Metadata.clientRecordId = "opencult:<measurement_uuid>:<record_type>"` and incrementing `clientRecordVersion`, preventing duplicate records across retries, edits, and historical backfills. | JVM unit test verifying deterministic IDs and update version increments. |
| `INV-05` | Instant Zero-Tap Health Connect Sync | With Health Connect permissions granted, locking a weigh-in triggers background `insertRecords` immediately without manual user export; soft-deleting a measurement triggers `deleteRecords` for its deterministic client IDs. | Integration test against fake/mock `HealthConnectClient`. |
| `INV-06` | Offline-First Local Durability | Room SQLite commits every weigh-in and queues a `sync_outbox` row locally in `< 50 ms` before any network or Health Connect call. Offline mode never drops or blocks a measurement. | Instrumented/Robolectric database test with network disabled. |
| `INV-07` | Zero-Refresh Realtime Convergence | While signed in and online, Supabase Realtime Postgres Changes (`measurements`, `household_profiles`, `scale_devices`, `health_connect_sync_ledger`) merge into Room and emit onto Kotlin `StateFlow` within `2 s` without manual refresh, ignoring self-echoes via `mutation_id`. | Sync engine unit test with simulated Realtime event + `mutation_id` dedup. |
| `INV-08` | Row-Level Security Enforcement | Every `public` table in Supabase Postgres has both `ENABLE ROW LEVEL SECURITY` and `FORCE ROW LEVEL SECURITY` scoped to `(SELECT auth.uid()) = account_id`. The Android client never holds `service_role`. | SQL migration inspection + cross-user isolation verification query. |
| `INV-09` | Household Ambiguity Safety | Up to 10 active household profiles are supported. Auto-recognition assigns a weigh-in automatically only when exactly one profile's recent rolling weight matches within its configured `auto_match_window_kg` (default `2.5 kg`). Zero or 2+ matches mark `assignment_state = 'pending_review'` for explicit user selection. | Unit tests for 0-match, 1-match, and 2-match household scenarios. |
| `INV-10` | Design Token Exclusivity | Screen composables never hardcode `Color(0x...)`, font sizes, or corner radii; all visual properties resolve through `OpenCultTheme` tokens (`DRD:T-*`). | Lint/grep check across `feature/` modules for raw color or sp/dp literals outside `designsystem`. |
| `INV-11` | Custom Canvas Chart Fidelity | `DRD:C-01` capsule spark-bars, `DRD:C-02` bezier waves, `DRD:C-03` 3-zone segmented arc gauge, `DRD:C-04` stippled dot-matrix bar chart, and `DRD:C-06` 5-segment anatomical body map are drawn via Compose `Canvas` / `DrawScope`, never substituted with stock generic charts. | Code inspection + Compose screenshot verification against `DRD.md`. |
| `INV-12` | Tabular Numerals on Telemetry | Every live weight, heart-rate, impedance, and metric readout uses `fontFeatureSettings = "tnum"` so streaming updates never jitter horizontally. | Typography token check + Compose semantics test. |
| `INV-13` | Floating Dock Inset Clearance | Every scrollable screen adds `dockHeight + navigationBarsPadding + 24.dp` bottom content padding so the detached `#0F1115` dock and `#2185F7` Measure FAB never clip content. | Compose layout bounds test on compact (`360dp` width) viewport. |
| `INV-14` | Dual-Scale Coexistence | Both Cult Smart Scale Pro (8-electrode `CULT*`) and Cult Smart Body Fat Scale (4-electrode `CS-BF01`) pair and log to the same household account without re-onboarding or schema changes. | `ScaleProtocolRouter` unit test switching between `0xCF` weight-only and `0xCF + 0xBE + 0xDF` streams. |
| `INV-15` | Secret and Reference Exclusion | `Both/`, `.env` / `.env.*` (except `.env.example`), keystores, and credentials remain ignored by `.gitignore` and never enter git commits. | `git check-ignore` + secret regex gate prior to every commit. |
| `INV-16` | Tombstone Soft Delete | Deleting a measurement sets `deleted_at` rather than hard-deleting locally first, so soft deletes propagate across Supabase Realtime and Health Connect before optional compaction. | Sync + Health Connect deletion propagation test. |
| `INV-17` | Android Form Factor and Full Navigation Coverage | Prototypes and builds target Android handset geometry (punch-hole camera cutout, system gesture bar, Android insets, zero iOS chrome) and provide uninterrupted navigation across all 9 flows (`DRD:S-01`..`S-09`) (`SHAME-001`). | Prototype DOM check + Compose navigation graph test verifying reachability of `S-01`..`S-09`. |
| `INV-18` | Micro-Action Contract and Hitbox Minimum | Every interactive control satisfies Touchdown/Tracking/Payoff/Consequence (`MICROENGINEERING.md §2`) with `>= 48.dp x 48.dp` Compose touch targets (`>= 44 px` in prototype) and zero hover-only controls (`SHAME-002`, `SHAME-003`). | Compose semantics `minTouchTarget` assertion + compact `360.dp` overflow check. |
| `INV-19` | Closed Motion Tokens and Telemetry Damping | Every animation resolves through `OpenCultMotion` (`MOTIONENGINEERING.md §2`); live `0xCF` weight, sweep rings, and curved `DRD:C-03` arc thumbs use damped polar/telemetry specs (`dampingRatio >= 0.82f`), GPU `graphicsLayer` transforms, and zero Cartesian arc shortcuts or layout-thrashing height loops. | Token audit + Compose `AnimationClock` test on weigh-in ticker and polar arc thumb interpolation. |
| `INV-20` | Reduced Motion and Lifecycle Loop Containment | Infinite animations (`AmbientRadar` Stage 1 rings) run only when that screen is foregrounded (`STARTED`) and actively scanning, and disable immediately when `ANIMATOR_DURATION_SCALE == 0f` or `prefers-reduced-motion: reduce` is active (`DRD:M-02`, `MOTIONENGINEERING.md §4-5`). | Instrumented test under `ANIMATOR_DURATION_SCALE=0f` + background/dismiss lifecycle cancellation check. |
| `INV-21` | Coalesced Duplicate BLE Frame Disambiguation | `ScaleProtocolRouter` distinguishes 20-byte ATT-coalesced duplicate final `0xCF` frames from 18-byte+ `OneByone` history records using frame header, XOR checksum, and second-frame marker checks (`SHAME-005`), and deduplicates lock writes and haptics per weigh-in lock event. | Parameterized unit test covering 11B live, 20B coalesced duplicate, and 18B genuine history fixtures. |
| `INV-22` | Canonical Spec Over Prototype Drift Guard | Where any visual token in `prototype/` drifts from `DRD.md` (currently `SHAME-006`: `DRD:C-03` arc zone palette `#2185F7`/`#F4B428`/`#EF4444` with `4 deg` gaps vs prototype `#3B82F6`/`#34C77B`/`#F4B428` with `8 deg` gap, plus staggered `DRD:C-04` stipples), native Android Compose follows `DRD.md` and `MICROENGINEERING.md`. | Screenshot/Canvas parameter test comparing Compose gauge colors, gaps, and dot offsets against `DRD.md`. |
| `INV-23` | Dual-Ledger Bug Regression Mandate | Every bug fix (BLE, BIA, Health Connect, Sync, UI, or Motion) MUST atomically update `HALL_OF_SHAME.md` AND add/tighten an invariant here (plus `MICROENGINEERING.md` or `MOTIONENGINEERING.md` for UI/motion issues) alongside a regression test in the same commit. | Git diff / PR gate verifying bug-fix commits update both `HALL_OF_SHAME.md` and `INVARIANTS.md` with test coverage. |
| `INV-24` | Least-Privilege Release Manifest and Play Protect Hygiene | Final merged release APK (`aapt2 dump permissions`) declares zero restricted/advertising/location permissions (`BLUETOOTH_ADVERTISE`, `ACCESS_FINE_LOCATION`, `REQUEST_INSTALL_PACKAGES`), uses `allowBackup="false"`, `usesCleartextTraffic="false"`, fails release signing on missing keystore, and leaks zero secrets or debug symbols. | `aapt2 dump permissions`, `apksigner verify --print-certs`, and APK archive secret scan on `app-release.apk`. |
| `INV-25` | Cold-Launch Activity and Dispatcher Integrity Gate | `MainActivity` must boot to an interactive UI frame without missing CompositionLocals (`LocalNavigationEventDispatcherOwner`), R8 reflection stripping, or ANRs across both Robolectric `ActivityScenario` smoke checks and live Android emulator release APK launch. | Robolectric `MainActivity` setup test + live `adb install -r app-release.apk` & `am start` with zero `AndroidRuntime` fatal exceptions. |
| `INV-26` | Honest Empty States and Strict Hardware/Audio Boundaries | Main-source UI routes contain zero demo data seeders or hardcoded body composition fallbacks (`16.5%` replaced with `--%`, `hasData = false`). Onboarding and live weigh-in expose only verified physical Cult hardware SKUs (`Cult Smart Scale Pro` and `CS-BF01`), with clinical 44.1 kHz PCM cues (`:core:audio`) gated by system ringer mode and user toggle. | `HomeScreenTest`, `ReportsScreenTest`, `OnboardingScreenTest`, `PcmSoundSynthesizerTest`. |
| `INV-27` | Active Member Session, Orphan-Safe HC Reassignment, and Opt-In Imports | All UI routes observe shared `ActiveMemberSession`. Reassigning a pending weigh-in deletes prior Member A Health Connect records, recalculates `M-01..M-56` against Member B anthropometry, and writes back only if Member B `isPrimaryHcUser`. External HC weight changes use deterministic RFC-4122 UUIDs (`health_connect_import`) and opt-in Resting HR / background permissions remain disabled until toggled. | `HealthConnectGatewayTest`, `DatabaseAndMatcherTest`, `InspectorScreenTest`, `WeighInScreenTest`. |
| `INV-28` | Multi-Module Test Discovery, Minimal R8 Keep Surface, and CI Hygiene | Every Gradle module with Android or Hilt test sources runs real automated assertions under `testDebugUnitTest` without suppressing `failOnNoDiscoveredTests`. Release R8 configuration avoids blanket package-wide `Companion` rules (`analyzeReleaseR8Config`), and workflows exclude `Both/**` reference code from CodeQL while signing commits exclusively via user SSH keys. | Full 14-module `.\gradlew.bat testDebugUnitTest :app:analyzeReleaseR8Config`, `r8-analyzer` Path A report, CI workflow checks. |
| `INV-29` | Two-Band Cole Physics and 4-Compartment Conservation | Dual-frequency `CULT_PRO_8E` water/impedance modeling computes `R0` and `Rinf` via two-band Cole-Cole bisection and derives `ECW` via De Lorenzo Eq. B2 (`ECW + ICW == TBW`), while `Protein = FFM - TBW - Mineral` enforces 4-compartment weight conservation (`SHAME-020`). | `BodyMetricsEngineTest` assertions on Cole ordering (`R0 > Zlow > Zhigh > Rinf`) and 4-compartment sum. |
| `INV-30` | Multi-Member Packet Sync Integrity and Remote Pull | Outbox drain looks up raw BLE packets directly by primary key (`RawBlePacketDao.getById`) across all up to 10 household profiles, and authentication triggers RLS-scoped remote pull + push (`SHAME-021`). | `Daos` + `SupabaseSyncTest` + Inspector Sync UI check. |
| `INV-31` | Health Connect Feature Gating, Expired-Token Recovery, and Usage Rationale | Optional `HealthConnectFeatures` (`HISTORY`, `IN_BACKGROUND`) are queried before requesting those scopes, `changesTokenExpired` triggers a 30-day catch-up `WeightRecord` read, and `MainActivity` handles both `ACTION_SHOW_PERMISSIONS_RATIONALE` and `Intent.ACTION_VIEW_PERMISSION_USAGE` (`SHAME-022`). | `HealthConnectGatewayTest` feature-gate test + Manifest/Activity intent inspection. |
